Before You StartWhat This Book Is

Functional Programming in Scala by Paul Chiusano and Rúnar Bjarnason (Manning; second edition with Michael Pilquist) teaches FP by having you derive everything yourself: you write a list, an optional value, a parallelism library, a test framework and a parser library, and then notice that they all share the same shapes. That arc is what makes the book worth reading, and it's the arc this companion follows.

The ideas aren't about Scala, so here every concept is taught in C++23: std::optional and std::expected, lambdas, concepts, std::variant, ranges and templates. Where C++ makes something harder (no guaranteed tail calls, no persistent containers, no do-notation, no direct way to abstract over F<_>), the chapter shows the workaround and why it's needed. In the book (Scala) boxes map each idea back to the original, so you can read the two side by side.

This isn't a copy of the book: it's my own walk-through of its concepts, in my own words and code, written to be read on an iPad. Every code block comes from a chapter file that was compiled with g++ 13 and run with its tests (and with AddressSanitizer and UndefinedBehaviorSanitizer).

Functional programming is not a style of writing code. It's one constraint: write programs out of pure functions. Everything else in this book (immutable data, optional, monads, IO) is what you discover you need once you take that one constraint seriously.

How To Read ItThe Rhythm of a Chapter

Every chapter has the same parts:

  • The problem first. Each idea is introduced by something that hurts without it.
  • Step-by-step derivation. Small code blocks, each one change from the last. Read them in order.
  • Boxes. Analogy for intuition, In the book (Scala) for how the original expresses it, Hold onto this for the one sentence to remember, Things that bite for common mistakes (several are C++-specific).
  • Exercises. Try each one before opening the solution. In FP the struggle with the types is the learning.
  • Recap and jargon decoder at the end, for review, and a link to the chapter's full runnable .cpp file.

ContentsFifteen Chapters, Four Parts

Part I (Ch. 1–6) gives you the basics: pure functions and the core data types. Part II (Ch. 7–9) designs three real libraries the functional way. Part III (Ch. 10–12) pulls the shared structure out of those libraries: monoids, monads, applicatives. Part IV (Ch. 13–14) handles the outside world: I/O, mutation and streams.

PacingA Realistic Plan

At about an hour a day: Part I takes two weeks. Do every exercise there, because the rest of the book assumes it's automatic. Part II takes two weeks. Read for the design process, not the specific library. Part III takes a week and a half and is where it clicks. Part IV takes a week. If you're short on time, read 1 → 3 → 4 → 6 → 10 → 11 → 13. That path covers the ideas with the most day-to-day payoff in C++: pure cores, errors as values, state as data, parallel reductions and composable effects.
