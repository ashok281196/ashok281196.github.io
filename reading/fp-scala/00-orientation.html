Orientation & Setup

What the red book is trying to teach, how to study a book made of exercises, and just enough Scala 3 to read every code block in this companion.

0.1Why This Book Has a Reputation

Most programming books show you finished tools and explain how to use them. The red book does the reverse. It gives you a constraint, no side effects, and then asks you to build the tools yourself, one exercise at a time. You write a linked list. Then an optional value. Then a random number generator that never mutates anything. Around chapter 6 you notice that the last three things you built have methods with exactly the same shape. Around chapter 11 the book names that shape: a monad.

That's why people call it hard and also why they call it the best FP book. The difficulty isn't the syntax. You're asked to discover the abstractions rather than be told them, and discovering takes effort.

Learning FP from a list of definitions ("a monad is a type with flatMap and unit satisfying three laws") is like learning chess from the rulebook. The red book makes you play hundreds of small games first, so when you finally read the rule, you've already used it.

0.2How to Study It

  1. Read the signature, then stop. Most exercises give you a type signature like def map[A, B](as: List[A])(f: A => B): List[B]. Before writing anything, ask: what values do I have, what do I need to produce, and what can I do with what I have? Often only one implementation compiles.
  2. Write it on paper or in a REPL, not in your head. The compiler is your teacher here. Type errors are hints.
  3. Get stuck for ten minutes, not two hours. If you can't see it after ten honest minutes, open the solution, understand it, close it, and write it again from memory the next day.
  4. Re-derive, don't memorise. The goal is to be able to reconstruct foldRight or flatMap for a new type, not to remember the one for List.
When you're stuck on an FP exercise, follow the types. Write down every value you have in scope and its type. The answer is almost always "combine these in the only way that makes the types line up."

0.3A Five-Minute Toolchain

You don't need sbt, an IDE project or a build file to follow this book. scala-cli runs single files and has a REPL.

On macOS or Linux:

# install (macOS)
brew install Virtuslab/scala-cli/scala-cli

# or Linux
curl -sSLf https://scala-cli.virtuslab.org/get | sh

# a REPL
scala-cli repl

# run a file
scala-cli run Hello.scala

On the iPad itself you can't install a JVM, but Scastie runs Scala 3 in the browser. Set the target to Scala 3 in Build Settings and paste any code block from this book.

Your first file:

// Hello.scala
@main def hello(): Unit =
  val xs = List(1, 2, 3)
  println(xs.map(_ * 10))   // List(10, 20, 30)

0.4Scala 3 in One Sitting

This is the subset of Scala that the rest of the companion uses. Skim it now and come back when a later code block looks unfamiliar.

Values and methods

val x: Int = 42            // immutable binding (like `const auto` in C++)
var y = 0                  // mutable; we'll almost never use this
def square(n: Int): Int = n * n
def add(a: Int, b: Int) = a + b      // return type inferred

// Scala 3 allows indentation instead of braces
def describe(n: Int): String =
  if n < 0 then "negative"
  else if n == 0 then "zero"
  else "positive"

Everything is an expression: if returns a value, a block returns its last line, and there's no need for return.

Functions as values

val inc: Int => Int = n => n + 1     // a function value
val twice = (f: Int => Int, x: Int) => f(f(x))
twice(inc, 5)                         // 7
List(1, 2, 3).map(_ + 1)              // `_ + 1` is shorthand for x => x + 1

Generics use square brackets

def first[A](xs: List[A]): A = xs.head     // like template<typename A>

Enums and pattern matching

enum Shape:
  case Circle(r: Double)
  case Rect(w: Double, h: Double)

import Shape.*
def area(s: Shape): Double = s match
  case Circle(r)  => math.Pi * r * r
  case Rect(w, h) => w * h

Traits, case classes, objects

trait Greeter:                 // like an abstract class / interface
  def greet(name: String): String

case class Point(x: Int, y: Int)    // immutable record with equals, copy, pattern matching
val p = Point(1, 2)
val q = p.copy(y = 5)               // Point(1, 5); p is unchanged

object MathUtil:                    // a singleton; home for "static" functions
  def clamp(n: Int, lo: Int, hi: Int) = n.max(lo).min(hi)

Extension methods

extension (s: String)
  def shout: String = s.toUpperCase + "!"

"hi".shout   // "HI!"

We'll use extension methods a lot. They let us write opt.map(f) on a type we define ourselves, without putting every method inside the type.

Some quick mappings. val is const. A trait is an abstract base class that can also carry implementations. [A] is template<typename A>, but the generic code is checked once at the definition, not at each use. An enum with cases is a std::variant where pattern matching is a type-checked std::visit, and the compiler warns if you forget a case. A => B is std::function<B(A)>.

0.5A Word on Our Naming

Scala's standard library already has List, Option, Either and LazyList. In chapters 3–5 we build our own versions to understand them. To avoid clashes, put each chapter's code in its own file, or wrap it in an object, and hide the standard names when needed:

import scala.{Option as _, Some as _, None as _, Either as _, Left as _, Right as _}

Install scala-cli (or open Scastie), and write a function isSorted[A](as: List[A], gt: (A, A) => Boolean): Boolean that returns true if no element is "greater than" the one after it. Use a match. Don't worry about elegance yet.

Show solution
def isSorted[A](as: List[A], gt: (A, A) => Boolean): Boolean = as match
  case a :: b :: rest => !gt(a, b) && isSorted(b :: rest, gt)
  case _              => true      // empty or single element

isSorted(List(1, 2, 3), _ > _)    // true
isSorted(List(1, 3, 2), _ > _)    // false

a :: b :: rest matches a list with at least two elements. Note the function is generic: it doesn't know what A is, so it must use gt to compare. That's your first taste of types constraining an implementation.
