Parser Combinators

The purest exercise in algebraic design: write the whole interface of a parsing library, and a JSON parser using it, before deciding how a parser is represented. Then implement a dozen primitives and watch everything else work.

9.1What We're Building

A parser turns unstructured text into structured data: "[1, 2, true]" into a JSON array value. A parser combinator library gives you small parsers (match a string, match a digit) and functions that combine them (this then that, this or that, many of this). You build a full parser in code, with no separate grammar file or generator step.

This chapter pushes "algebra first" to its limit. We'll write the API as a trait with an abstract type Parser[+A], use it to write a JSON parser, and only at the end choose a representation.

9.2Primitives, From Examples

Start with the simplest things we'd want to parse, and invent a function for each:

trait Parsers[Parser[+_]]:
  def string(s: String): Parser[String]          // match exactly s
  def char(c: Char): Parser[Char] = string(c.toString).map(_.charAt(0))
  def succeed[A](a: A): Parser[A]                // consume nothing, always succeed

  extension [A](p: Parser[A])
    def run(input: String): Either[ParseError, A]
    infix def or(p2: => Parser[A]): Parser[A]    // try p; if it fails, try p2
    def |(p2: => Parser[A]): Parser[A] = p.or(p2)

Parsers[Parser[+_]] is new: Parser is a type constructor parameter, a type that takes a type. The trait is generic over how parsers are represented. Any implementation must supply these functions for its own Parser type.

Laws come immediately:

string(s).run(s)          == Right(s)
succeed(a).run(anything)  == Right(a)
(string("ab") | string("cd")).run("cd") == Right("cd")

Repetition

Parse "zero or more of p", and "exactly n of p":

  extension [A](p: Parser[A])
    def many: Parser[List[A]]
    def listOfN(n: Int): Parser[List[A]]
    def map[B](f: A => B): Parser[B]

Counting characters is now char('a').many.map(_.size). That builds a list just to count it. A better primitive: slice, which returns the part of the input a parser consumed, ignoring its result:

    def slice: Parser[String]

char('a').many.slice.map(_.size)   // no intermediate list

Sequencing

To parse "one or more a's", we need "p, then p.many". That needs a way to run two parsers in sequence:

    def product[B](p2: => Parser[B]): Parser[(A, B)]
    def **[B](p2: => Parser[B]): Parser[(A, B)] = product(p2)

    def map2[B, C](p2: => Parser[B])(f: (A, B) => C): Parser[C] =
      product(p2).map((a, b) => f(a, b))

    def many1: Parser[List[A]] =
      map2(p.many)(_ :: _)

Why is p2 by-name? Look at many written with map2:

    def many: Parser[List[A]] =
      p.map2(p.many)(_ :: _) | succeed(Nil)

If map2 evaluated p.many eagerly, it would call many again, forever. By-name makes the recursion lazy: the inner p.many is built only when parsing actually reaches it. Laziness from Chapter 5 is load-bearing here. So many is derived, not primitive.

Context sensitivity

Parse a digit n, then exactly n letter a's ("3aaa"). The second parser depends on the result of the first. map2 can't express that. You know what can:

    def flatMap[B](f: A => Parser[B]): Parser[B]

val countedAs: Parser[Int] =
  for
    digit <- regex("[0-9]".r)
    n = digit.toInt
    _     <- char('a').listOfN(n)
  yield n

With flatMap, product and map become derived too (exercise). regex is another primitive: def regex(r: scala.util.matching.Regex): Parser[String].

Write product and map using flatMap and succeed.

Show solution
    def product[B](p2: => Parser[B]): Parser[(A, B)] =
      p.flatMap(a => p2.map(b => (a, b)))

    def map[B](f: A => B): Parser[B] =
      p.flatMap(a => succeed(f(a)))

The same derivations as for Option, State and Par. succeed plays the role of unit.

Our primitive set is now: string, regex, succeed, slice, or, flatMap. Everything else (map, map2, product, many, many1, listOfN) is derived. An implementation only has to provide six functions.

9.3A JSON Parser, Before Any Implementation

JSON as an ADT:

enum JSON:
  case JNull
  case JNumber(get: Double)
  case JString(get: String)
  case JBool(get: Boolean)
  case JArray(get: IndexedSeq[JSON])
  case JObject(get: Map[String, JSON])

A few more derived helpers make grammars pleasant: skip whitespace, keep the left or right result of a sequence, and separate by a delimiter.

  def whitespace: Parser[String] = regex("\\s*".r)

  extension [A](p: Parser[A])
    def *>[B](p2: => Parser[B]): Parser[B] = p.slice.map2(p2)((_, b) => b)   // keep right
    def <*(p2: => Parser[Any]): Parser[A] = p.map2(p2.slice)((a, _) => a)    // keep left
    def token: Parser[A] = p <* whitespace
    def sep(separator: Parser[Any]): Parser[List[A]] =
      (p.map2((separator *> p).many)(_ :: _)) | succeed(Nil)
    def as[B](b: B): Parser[B] = p.slice.map(_ => b)

  def token(s: String): Parser[String] = string(s).token

Now the grammar, written only against the trait:

object JSON:
  def jsonParser[Parser[+_]](P: Parsers[Parser]): Parser[JSON] =
    import P.*

    def lit: Parser[JSON] = (
      token("null").as(JNull) |
      token("true").as(JBool(true)) |
      token("false").as(JBool(false)) |
      regex("-?[0-9]+(\\.[0-9]+)?([eE][-+]?[0-9]+)?".r).token.map(s => JNumber(s.toDouble)) |
      (string("\"") *> regex("[^\"]*".r) <* token("\"")).map(JString(_))
    )

    def array: Parser[JSON] =
      (token("[") *> value.sep(token(",")) <* token("]")).map(vs => JArray(vs.toIndexedSeq))

    def keyval: Parser[(String, JSON)] =
      (string("\"") *> regex("[^\"]*".r) <* token("\"")) ** (token(":") *> value)

    def obj: Parser[JSON] =
      (token("{") *> keyval.sep(token(",")) <* token("}")).map(kvs => JObject(kvs.toMap))

    def value: Parser[JSON] = lit | obj | array

    whitespace *> value

That's a whole JSON parser (simplified strings without escapes), and we still haven't decided what a Parser is. The grammar reads almost like the JSON spec. Mutual recursion between value, array and obj works because the combinators take by-name arguments.

Compare this to Boost.Spirit or PEGTL in C++: same idea (grammars as code, built from combinators), but those encode the grammar in template types and resolve it at compile time. Here a parser is an ordinary runtime value. That's slower, but you can build parsers dynamically, pass them to functions and test them like any other value.

9.4Error Reporting

A parser that says "failed" with no location is useless on real input. We want the position and a stack of human-readable context ("in array, in object, expected ':'"). Add two primitives:

  extension [A](p: Parser[A])
    def label(msg: String): Parser[A]   // on failure, replace the error message with msg
    def scope(msg: String): Parser[A]   // on failure, add msg as outer context

case class Location(input: String, offset: Int = 0):
  lazy val line = input.slice(0, offset + 1).count(_ == '\n') + 1
  lazy val col  = input.slice(0, offset + 1).lastIndexOf('\n') match
    case -1        => offset + 1
    case lineStart => offset - lineStart

case class ParseError(stack: List[(Location, String)])

Committed vs backtracking

There's a subtle design question in or. Parsing (string("abra") ** string("cadabra")) | other on "abraxyz": the left side matched "abra" then failed. Should or try other from the start? For good error messages, usually not: once a parser has consumed input, it has committed, and the error from that branch is the useful one. The solution is a combinator attempt(p) that explicitly allows backtracking:

    def attempt: Parser[A]   // if p fails after consuming input, treat it as not having consumed

By default, or only tries the right side if the left failed without consuming input. Many real parser libraries (Parsec, FastParse, cats-parse) make this same choice.

9.5Finally, a Representation

A parser takes input at some position and either fails with an error, or succeeds with a value and how many characters it consumed. A small, working version:

enum Result[+A]:
  case Success(get: A, consumed: Int)
  case Failure(get: ParseError, isCommitted: Boolean)

opaque type Parser[+A] = Location => Result[A]

object MyParsers extends Parsers[Parser]:
  def string(w: String): Parser[String] =
    l =>
      if l.input.startsWith(w, l.offset) then Result.Success(w, w.length)
      else Result.Failure(ParseError(List(l -> s"expected \"$w\"")), isCommitted = false)

  def regex(r: scala.util.matching.Regex): Parser[String] =
    l => r.findPrefixOf(l.input.substring(l.offset)) match
      case Some(m) => Result.Success(m, m.length)
      case None    => Result.Failure(ParseError(List(l -> s"expected $r")), false)

  def succeed[A](a: A): Parser[A] = _ => Result.Success(a, 0)

  extension [A](p: Parser[A])
    def run(input: String) = p(Location(input)) match
      case Result.Success(a, _)    => Right(a)
      case Result.Failure(err, _)  => Left(err)

    def slice: Parser[String] =
      l => p(l) match
        case Result.Success(_, n) => Result.Success(l.input.substring(l.offset, l.offset + n), n)
        case f: Result.Failure    => f

    infix def or(p2: => Parser[A]): Parser[A] =
      l => p(l) match
        case Result.Failure(_, false) => p2(l)      // uncommitted: try the alternative
        case r                        => r

    def flatMap[B](f: A => Parser[B]): Parser[B] =
      l => p(l) match
        case Result.Success(a, n) =>
          f(a)(l.copy(offset = l.offset + n)) match
            case Result.Success(b, m)   => Result.Success(b, n + m)
            case Result.Failure(e, c)   => Result.Failure(e, c || n > 0)  // consumed input → committed
        case f: Result.Failure => f

    def attempt: Parser[A] =
      l => p(l) match
        case Result.Failure(e, _) => Result.Failure(e, false)
        case s                    => s

    def label(msg: String): Parser[A] =
      l => p(l) match
        case Result.Failure(e, c) => Result.Failure(ParseError(List(l -> msg)), c)
        case s                    => s

    def scope(msg: String): Parser[A] =
      l => p(l) match
        case Result.Failure(e, c) => Result.Failure(ParseError((l -> msg) :: e.stack), c)
        case s                    => s

About 60 lines, and JSON.jsonParser(MyParsers).run("""{"a": [1, true, null]}""") works. Everything we wrote in 9.3 runs on this representation unchanged.

This simple many isn't stack-safe and substring copies. A production implementation makes many a primitive with a loop, works on offsets instead of substrings, and uses a faster representation. Those are representation changes. Because the JSON parser only uses the algebra, none of them would touch it.

9.6Part II in One Paragraph

Three libraries: parallelism, testing, parsing. Each was designed the same way: usage first, a small set of primitives, laws, representation last. And each ended up with unit/succeed, map, map2, flatMap and some kind of sequence or many. Part III gives that recurring shape names and writes it down once.

Parser combinator
A function that builds a parser from smaller parsers.
Type constructor
A type that takes a type parameter, like Parser[_] or List[_]. A trait can abstract over one.
Context-sensitive grammar
A grammar where what to parse next depends on what was just parsed; needs flatMap.
Commit / backtrack
Whether, after consuming input and failing, a parser lets an alternative retry from the original position.
  • Write the algebra (as a trait over an abstract Parser[+_]) before any implementation.
  • Six primitives are enough; many, map2 and friends are derived.
  • By-name parameters make recursive grammars work.
  • Design error reporting into the algebra: labels, scopes, commit vs attempt.
  • A 60-line representation runs a full JSON grammar written against the trait.
