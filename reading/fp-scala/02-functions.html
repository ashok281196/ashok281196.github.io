Functions, Recursion & Types

Loops without mutation, functions that take and return functions, and generic functions so constrained by their types that there's only one way to write them.

2.1Loops Become Recursion

If we can't mutate a counter, how do we loop? We write a function that calls itself with the next value of the counter. The "loop variables" become parameters.

// imperative
def factorialLoop(n: Int): Int =
  var acc = 1
  var i = n
  while i > 0 do
    acc *= i
    i -= 1
  acc

// recursive: acc and i become parameters of an inner function
def factorial(n: Int): Int =
  def go(i: Int, acc: Int): Int =
    if i <= 0 then acc
    else go(i - 1, acc * i)
  go(n, 1)

Read go as a loop body: "if we're done, return the accumulator; otherwise run again with i - 1 and an updated accumulator." This pattern, an inner go with an accumulator, is how you'll write most loops in FP.

Tail calls and the stack

Doesn't recursion blow the stack? It depends where the recursive call sits. In go, the call go(i - 1, acc * i) is the last thing the function does. Nothing is waiting for its result. That's a tail call, and the Scala compiler turns tail-recursive functions into a plain while loop in bytecode, so there's no stack growth.

import scala.annotation.tailrec

def factorial(n: Int): Int =
  @tailrec
  def go(i: Int, acc: Int): Int =
    if i <= 0 then acc
    else go(i - 1, acc * i)
  go(n, 1)

@tailrec asks the compiler to fail if it can't make the function a loop. Use it every time you mean "this is a loop".

Compare a non-tail-recursive version:

def factorialNaive(n: Int): Int =
  if n <= 0 then 1
  else n * factorialNaive(n - 1)   // must multiply AFTER the call returns

After the recursive call returns, we still need to multiply by n. Each frame waits, so a deep input overflows.

C++ compilers often do tail-call optimisation at -O2, but the standard doesn't guarantee it, so you can't rely on it. In Scala, @tailrec turns it into a compile-time guarantee for self-recursive functions. (Mutual recursion and recursion through closures aren't covered; Chapter 13 handles those with trampolining.)

Write a tail-recursive fib(n: Int): Int returning the n-th Fibonacci number, where fib(0) = 0, fib(1) = 1.

Show solution
def fib(n: Int): Int =
  @tailrec
  def go(k: Int, prev: Int, cur: Int): Int =
    if k == 0 then prev
    else go(k - 1, cur, prev + cur)
  go(n, 0, 1)

Two accumulators: the pair (prev, cur) slides along the sequence. Each step is (a, b) → (b, a + b).

2.2Higher-Order Functions

Functions are values. You can pass them in, return them, and store them. A function that takes or returns another function is a higher-order function (HOF).

Suppose we print the absolute value and the factorial of a number:

def formatAbs(x: Int) = s"The absolute value of $x is ${x.abs}"
def formatFactorial(n: Int) = s"The factorial of $n is ${factorial(n)}"

They differ only in a name and a function. Pull the difference out as parameters:

def formatResult(name: String, n: Int, f: Int => Int): String =
  s"The $name of $n is ${f(n)}"

formatResult("absolute value", -42, _.abs)
formatResult("factorial", 7, factorial)

That's the basic FP move: whatever varies becomes a function parameter.

2.3Polymorphic Functions

Here's a search that only works on arrays of strings:

def findFirst(ss: Array[String], key: String): Int =
  @tailrec
  def loop(i: Int): Int =
    if i >= ss.length then -1
    else if ss(i) == key then i
    else loop(i + 1)
  loop(0)

Nothing about the algorithm depends on strings. Generalise the element type to A, and since we can't compare an unknown A to a key, take a predicate:

def findFirst[A](as: Array[A], p: A => Boolean): Int =
  @tailrec
  def loop(i: Int): Int =
    if i >= as.length then -1
    else if p(as(i)) then i
    else loop(i + 1)
  loop(0)

findFirst(Array(7, 9, 13), _ == 9)   // 1

A function with type parameters is polymorphic (more precisely, parametrically polymorphic). It must work the same way for every A, so it can't inspect or create As. It can only move around the ones it's given.

2.4Following the Types to the Implementation

That restriction is powerful: the less a function knows about its types, the fewer ways there are to write it. Sometimes there's exactly one.

Take this signature:

def partial1[A, B, C](a: A, f: (A, B) => C): B => C

Reason it through:

  1. We must return a B => C, a function. So start with b => ???.
  2. Inside, we must produce a C. The only thing that produces a C is f.
  3. f needs an A and a B. We have a and, inside the lambda, b.
def partial1[A, B, C](a: A, f: (A, B) => C): B => C =
  b => f(a, b)

No cleverness required. The types left only one option. You'll use this technique for the whole book.

With a generic signature, ask: what do I have, what do I need, and which values produce the thing I need? Then fill in the holes. Scala lets you write ??? as a placeholder that compiles, so you can work one hole at a time.

Implement def curry[A, B, C](f: (A, B) => C): A => (B => C). It turns a two-argument function into a function that takes the arguments one at a time.

Show solution
def curry[A, B, C](f: (A, B) => C): A => (B => C) =
  a => b => f(a, b)

Implement the reverse: def uncurry[A, B, C](f: A => B => C): (A, B) => C.

Show solution
def uncurry[A, B, C](f: A => B => C): (A, B) => C =
  (a, b) => f(a)(b)

Note that => associates to the right: A => B => C means A => (B => C).

Implement def compose[A, B, C](f: B => C, g: A => B): A => C.

Show solution
def compose[A, B, C](f: B => C, g: A => B): A => C =
  a => f(g(a))

The standard library has it as f.compose(g) or g.andThen(f).

2.5Anonymous Functions and Shorthand

Scala gives you several ways to write the same function value. You'll see all of them in real code:

(x: Int) => x + 1      // full form
x => x + 1             // type inferred from context
_ + 1                  // placeholder: each _ is the next argument
(a, b) => a + b
_ + _                  // same as above

Underneath, a function value is an object with an apply method. f(x) is f.apply(x).

_ shorthand gets confusing quickly. _ + _ is a two-argument function, not "x plus x". And f(_ + 1) means f(x => x + 1), which is often right but not always. When in doubt, name the parameter.

2.6Why "Point-Free" Code Shows Up

Once functions compose, you can describe a pipeline without mentioning the data:

val trim: String => String = _.trim
val lower: String => String = _.toLowerCase
val normalise = trim.andThen(lower)

List("  Hello", "WORLD ").map(normalise)   // List("hello", "world")

You'll see this a lot in FP code. Use it where it reads well and name intermediate values where it doesn't.
