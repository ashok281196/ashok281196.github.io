Monads

Since Chapter 3 we've written unit, map, map2, flatMap and sequence over and over. Here we write them once. First Functor (things you can map), then Monad (things you can flatMap), their laws, and what a monad means once you've seen enough of them.

11.1The Duplication Problem

Here's map2 for four types we've written:

// Option
def map2[A, B, C](fa: Option[A], fb: Option[B])(f: (A, B) => C) = fa.flatMap(a => fb.map(b => f(a, b)))
// State
def map2[A, B, C](fa: State[S, A], fb: State[S, B])(f: (A, B) => C) = fa.flatMap(a => fb.map(b => f(a, b)))
// Gen
def map2[A, B, C](fa: Gen[A], fb: Gen[B])(f: (A, B) => C) = fa.flatMap(a => fb.map(b => f(a, b)))
// Parser
def map2[A, B, C](fa: Parser[A], fb: Parser[B])(f: (A, B) => C) = fa.flatMap(a => fb.map(b => f(a, b)))

The bodies are character-for-character identical. Only the type constructor differs. In C++ you'd reach for a template over the container template. In Scala we abstract over the type constructor F[_], as we did with Parsers and Foldable.

11.2Functor: Things You Can Map

Start with the smallest piece: map.

trait Functor[F[_]]:
  extension [A](fa: F[A])
    def map[B](f: A => B): F[B]

given Functor[List] with
  extension [A](as: List[A])
    def map[B](f: A => B): List[B] = as.map(f)

A functor is a type constructor with a map that obeys two laws:

fa.map(identity)    == fa                    // identity
fa.map(f).map(g)    == fa.map(f.andThen(g))  // composition

The first is the law from Chapter 7: map preserves structure. It can't drop list elements, swap Some to None, or change how many items there are. It only transforms values.

With just map we can already write generic functions:

  extension [A, B](fab: F[(A, B)])
    def distribute: (F[A], F[B]) = (fab.map(_(0)), fab.map(_(1)))   // "unzip" for any functor

11.3Monad: Things You Can flatMap

We've seen many times that unit and flatMap are enough to derive map, map2, sequence and traverse. So make them the primitives:

trait Monad[F[_]] extends Functor[F]:
  def unit[A](a: => A): F[A]

  extension [A](fa: F[A])
    def flatMap[B](f: A => F[B]): F[B]

    def map[B](f: A => B): F[B] =
      fa.flatMap(a => unit(f(a)))

    def map2[B, C](fb: F[B])(f: (A, B) => C): F[C] =
      fa.flatMap(a => fb.map(b => f(a, b)))

  def sequence[A](fas: List[F[A]]): F[List[A]] =
    traverse(fas)(identity)

  def traverse[A, B](as: List[A])(f: A => F[B]): F[List[B]] =
    as.foldRight(unit(List.empty[B]))((a, acc) => f(a).map2(acc)(_ :: _))

  def replicateM[A](n: Int, fa: F[A]): F[List[A]] =
    sequence(List.fill(n)(fa))

Now each type needs just two functions, and gets all the rest:

given optionMonad: Monad[Option] with
  def unit[A](a: => A) = Some(a)
  extension [A](fa: Option[A])
    override def flatMap[B](f: A => Option[B]) = fa.flatMap(f)

given listMonad: Monad[List] with
  def unit[A](a: => A) = List(a)
  extension [A](fa: List[A])
    override def flatMap[B](f: A => List[B]) = fa.flatMap(f)

summon[Monad[Option]].sequence(List(Some(1), Some(2)))   // Some(List(1, 2))
summon[Monad[List]].replicateM(2, List(0, 1))            // List(List(0,0), List(0,1), List(1,0), List(1,1))

Look at replicateM. For Option it means "n copies, or None". For List it means "every combination of n choices". For Gen it means "a list of n random values" (that's listOfN). For Parser it means "parse exactly n times" (also listOfN). One generic function, a different meaningful behaviour for each monad.

State needs a type lambda

State[S, A] has two type parameters, but Monad wants a type constructor with one. Fix S and leave A open:

given stateMonad[S]: Monad[[x] =>> State[S, x]] with
  def unit[A](a: => A): State[S, A] = State.unit(a)
  extension [A](st: State[S, A])
    override def flatMap[B](f: A => State[S, B]): State[S, B] =
      State.flatMap(st)(f)

[x] =>> State[S, x] is a type lambda: a type-level function from x to State[S, x]. It's how you partially apply a type constructor.

11.4The Monad Laws

As with monoids, the laws define the abstraction. To state them neatly, use Kleisli composition: composing two "monadic functions" A => F[B] and B => F[C]:

def compose[A, B, C](f: A => F[B], g: B => F[C]): A => F[C] =
  a => f(a).flatMap(g)

Then the laws are:

compose(compose(f, g), h) == compose(f, compose(g, h))   // associativity
compose(f, unit)          == f                           // right identity
compose(unit, f)          == f                           // left identity

Those are exactly the monoid laws, with compose as the combine and unit as the identity. Written with flatMap they're less pretty but say the same thing:

x.flatMap(f).flatMap(g) == x.flatMap(a => f(a).flatMap(g))
x.flatMap(unit)         == x
unit(y).flatMap(f)      == f(y)
The associativity law is why for-comprehensions work. It guarantees that nesting a sequence of <- steps one way or another gives the same program, so you can extract any group of steps into a helper function without changing behaviour.

Write flatMap in terms of compose and unit. This shows compose + unit is another valid set of primitives.

Show solution
def flatMapViaCompose[A, B](fa: F[A])(f: A => F[B]): F[B] =
  compose((_: Unit) => fa, f)(())

Make a function that ignores its Unit argument and returns fa, compose it with f, and call it with (). There are three equivalent minimal sets: unit + flatMap, unit + compose, and unit + map + join (from Chapter 7).

11.5So What Is a Monad?

Look at the simplest possible monad, one that does nothing:

case class Id[A](value: A):
  def map[B](f: A => B): Id[B] = Id(f(value))
  def flatMap[B](f: A => Id[B]): Id[B] = f(value)

for
  a <- Id("Hello, ")
  b <- Id("monad!")
yield a + b       // Id("Hello, monad!")

With Id, a for-comprehension is just variable binding: val a = ...; val b = ...; a + b. Every other monad is "variable binding, plus something extra happens between the lines":

MonadWhat happens between steps
Idnothing; plain sequencing
Optionmay stop early with no result
Either[E, _]may stop early with an error
Listmay branch into many results (nondeterminism)
State[S, _]a state is threaded along
Genrandomness is threaded along
Parserinput position is threaded; may fail or backtrack
Parsteps may run on other threads
A monad is a programmable semicolon. In an ordinary language, ; means "do the next thing". A monad's flatMap lets you define what "next" means: stop if empty, try every branch, pass the state along, wait for a thread. The for-comprehension is the code; the monad is the rule for how the lines connect.

So a monad isn't a container, and it isn't specifically about side effects. It's a minimal interface (unit and an associative flatMap) for sequencing computations where each step can depend on the previous result. Different monads give that sequencing different extra behaviour.

11.6Reader: One More Useful Monad

Many functions need the same configuration passed in. The Reader monad represents "a computation that needs an R":

opaque type Reader[R, A] = R => A

object Reader:
  def apply[R, A](f: R => A): Reader[R, A] = f
  def ask[R]: Reader[R, R] = r => r            // read the environment
  extension [R, A](ra: Reader[R, A]) def run(r: R): A = ra(r)

  given readerMonad[R]: Monad[[x] =>> Reader[R, x]] with
    def unit[A](a: => A): Reader[R, A] = _ => a
    extension [A](fa: Reader[R, A])
      override def flatMap[B](f: A => Reader[R, B]): Reader[R, B] =
        r => f(fa(r))(r)              // same r goes to every step

case class Config(baseUrl: String, retries: Int)

val endpoint: Reader[Config, String] =
  for
    cfg <- Reader.ask[Config]
  yield s"${cfg.baseUrl}/v1/data?retries=${cfg.retries}"

endpoint.run(Config("https://api.example.com", 3))

It's dependency injection with no framework: functions describe what they need, and you supply it once at the top.

If you've written C++ functions that all take a const Context& as their first parameter and pass it to every callee, Reader is that pattern with the passing done for you by flatMap.

Monads don't compose in general. Option is a monad and State is a monad, but there's no generic way to make State[S, Option[A]] a monad from those two alone. Real code needs specific monad transformers (OptionT, EitherT, StateT in cats) or an effect type that bundles common capabilities (like cats-effect's IO or ZIO). Functors and the abstraction in the next chapter do compose.

Functor
A type constructor with a structure-preserving map.
Monad
A functor with unit and an associative flatMap that obeys identity laws.
Kleisli arrow
A function A => F[B]; Kleisli composition chains them with flatMap.
Type lambda
[x] =>> T[S, x]: a type constructor made by fixing some parameters of another.
Reader
The monad of computations that read a shared, read-only environment.
  • Abstract over the type constructor F[_] to write map2, sequence, traverse once.
  • Functor: map plus identity and composition laws.
  • Monad: unit + flatMap, plus associativity and identity laws (the monoid laws for Kleisli composition).
  • A monad defines what "do this, then that" means for a type.
  • Monads don't compose generically, which motivates the next chapter.
